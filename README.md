# Weather API — Тестовое задание

**Полноценная реализация backend-приложения для запроса погоды.**  
Всё взаимодействие происходит через встроенный **Django REST Framework Browsable API** — отдельный фронтенд не требуется.

---

## Краткое описание

Приложение позволяет:
- Получать текущую погоду по названию города через OpenWeatherMap
- Сохранять все запросы в базу данных
- Просматривать историю запросов с фильтрацией и пагинацией
- Использовать кэширование (Redis)
- Выбирать единицы измерения (Celsius / Fahrenheit)
- Экспортировать историю в CSV
- Проверять состояние системы через `/health/`

---

## Требования тестового задания и обоснование решений

### Использованный стек

| Компонент            | Технология                     | Обоснование |
|----------------------|--------------------------------|-------------|
| Язык                 | Python 3.12                    | Требование задания |
| Фреймворк            | Django 5.2 + DRF 3.15          | Один из разрешённых фреймворков. DRF даёт готовые инструменты: ViewSet, сериализаторы, пагинацию, фильтры, throttling, CSV-рендерер и удобный Browsable API |
| База данных          | PostgreSQL                     | Прямое требование задания |
| Кэширование          | Redis + django-redis           | Необходим для корректной работы кэша и rate limiting в Docker-среде |
| Контейнеризация      | Docker + docker-compose        | Требование задания + полная воспроизводимость окружения |
| Управление командами | Makefile (опционально)         | Удобство. При отсутствии make можно использовать чистые команды docker compose |
| Конфигурация         | django-environ + `.env`        | Чистое разделение кода и настроек |
| Тестирование         | Django + DRF TestCase          | Покрывают ключевые требования задания |

### Архитектурные решения
- Бизнес-логика вынесена в `weather/services/` 
- Каждый запрос погоды **всегда** сохраняется в БД — согласно требованию п.4
- Конвертация единиц измерения выполняется на лету при использовании кэша для снижения количества запросов к внешнему API
- Используется структурированное логирование (ключ=значение)

### Соответствие требованиям
Реализованы **все 11 пунктов** тестового задания (см. код, тесты и этот README).

## Установка

1. Клонируйте репозиторий
2. Скопируйте файл окружения:
   ```bash
   cp env.sample .env
   ```
3. Укажите свой ключ OpenWeatherMap в `.env`:
   ```env
   WEATHER_API_KEY=ваш_ключ_здесь
   ```

**Требования:**
- Docker Desktop
- (Опционально) `make` — для удобства (на Windows часто отсутствует)

---

## Первый Запуск

### Вариант 1 — через Makefile (рекомендуется)

```bash
make build
make up
```

### Вариант 2 — без make (чистые команды Docker)

```bash
docker compose -f docker_compose.yaml build
docker compose -f docker_compose.yaml up -d
```

После запуска приложение доступно по адресу: **http://localhost:8000**

---

## API (Использование)

Всё делается через встроенный **Django REST Framework Browsable API**.

1. Откройте в браузере:  
   http://localhost:8000/api/weather/

2. Используйте форму **POST** для получения погоды:

```json
{
  "city": "Moscow",
  "units": "celsius"
}
```

### Основные эндпоинты

| Метод | Эндпоинт                        | Описание                              |
|-------|----------------------------------|---------------------------------------|
| POST  | `/api/weather/`                  | Получить погоду и сохранить запрос    |
| GET   | `/api/weather/`                  | История запросов (фильтры + пагинация)|
| GET   | `/api/weather/export-csv/`       | Экспорт истории в CSV                 |
| GET   | `/health/`                       | Проверка состояния системы            |

**Фильтры истории:**
- `?city=moscow`
- `?date_from=2026-01-01T00:00:00Z&date_to=2026-05-01T00:00:00Z`
